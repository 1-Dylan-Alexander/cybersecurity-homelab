# LAB-003 — Splunk Security Monitoring: Repeated Sudo Authentication Failures

[← Portfolio home](../../README.md) · [SPL detection](detections/repeated-sudo-failures.spl) · [Investigation report](evidence/investigation-report.md)

> **Status:** Completed and validated in a controlled Linux homelab on October 16, 2026. **Classification:** Authorized simulation; no unauthorized account access established.

## Executive summary

Built an SPL search that parsed Linux sudo summary messages from `/var/log/auth.log`, aggregated failed-attempt counts into five-minute buckets, and triggered a scheduled **medium-severity alert** after a controlled test generated a message reporting **three incorrect password attempts**. The result was documented with a short analyst-style investigation report.

## Objective and environment

- **Question:** Can a scheduled SIEM detection identify repeated failed sudo authentication in Linux logs?
- **Log source:** Linux Mint 22.3 host, `/var/log/auth.log`, indexed by Splunk Enterprise 10.6, `linux_secure` sourcetype.
- **Analysis:** Splunk Processing Language (SPL) using `rex`, `eval`, `bin`, `stats`, and `where`.
- **Alert:** Scheduled every five minutes; trigger condition: at least one matching search result; severity: Medium.

## Detection logic

The complete, reusable query is in [`detections/repeated-sudo-failures.spl`](detections/repeated-sudo-failures.spl).

1. Filter for sudo messages containing `incorrect password attempts`.
2. Extract the account and the reported number of failures with a regular expression.
3. Convert the extracted value to a number.
4. Aggregate counts by host, account, and **fixed five-minute time bin**.
5. Return only bins meeting the **three-failure threshold**.

**Interpretation:** This sums counts reported in sudo summary messages; it does not necessarily identify three independent log records or cover all Linux authentication failures.

| Local time (PDT) | Evidence | Interpretation |

| 14:14:40 | PAM recorded an authentication failure | Failed authentication activity observed |
| 14:14:47 | sudo reported three incorrect password attempts | Detection threshold met |

See the [investigation report](evidence/investigation-report.md) for event interpretation and operational settings. The test was generated by the lab operator; **no attacker or production SOC incident is claimed**.

## Limitations and future tuning

- Looks for a particular sudo message format; it is **not** comprehensive PAM or SSH detection.
- Fixed five-minute bins can split activity across window boundaries.
- The report records a scheduled search window of `-10m@m` through `-5m@m`; different scheduling or ingestion latency may change results.
- Log rotation, parsing variations, alert suppression, and false-positive triage require additional evaluation.
